1. CSS 与 JS 本地化规范
1.1 禁止使用第三方 CDN 资源
❌ 禁止	✅ 允许
<script src="https://cdn.jsdelivr.net/...">	<script src="/js/app.js">
<link rel="stylesheet" href="https://cdn...">	<link rel="stylesheet" href="/css/style.css">
@import url('https://fonts.googleapis.com/...')	使用系统字体栈
任何第三方在线资源	所有资源存放于项目 public/css/ 或 public/js/ 目录
1.2 例外情况
以下情况可破例使用第三方资源（需在代码中标注说明）：

图标字体 — 可使用 Font Awesome 等（但建议使用 Unicode/emoji 替代）

富文本编辑器 — 如需集成 TinyMCE 等，需用户明确要求

图表库 — 如需集成 ECharts 等，需用户明确要求

2. W3C 开发标准规范
2.1 HTML 标准
要求	说明
DOCTYPE	必须声明 <!DOCTYPE html>
字符编码	必须声明 <meta charset="UTF-8">
视口设置	必须声明 <meta name="viewport" content="width=device-width, initial-scale=1.0">
语义化标签	使用 <header>、<nav>、<main>、<article>、<section>、<footer> 等
img 标签	必须包含 alt 属性
a 标签	必须包含 href 属性
表单控件	必须包含 <label> 并正确关联 for / id
属性规范	属性值必须使用双引号包裹
标签闭合	所有标签必须正确闭合
2.2 CSS 标准
要求	说明
选择器命名	使用 BEM 或语义化命名（如 .article-card、.nav-link）
注释规范	重要模块添加注释说明
单位使用	优先使用 rem / em，避免 px（边框除外）
颜色使用	使用 CSS 变量（var(--primary)）便于主题切换
2.3 CSS 格式规范
所有 CSS 规则必须保持单行格式：

css
/* ✅ 正确 — 单行格式 */
.site-header { background: var(--bg-card); border-bottom: 1px solid var(--border); padding: var(--spacing-md) 0; position: sticky; top: 0; z-index: 100; box-shadow: var(--shadow); }

.logo { font-size: 1.5rem; font-weight: 800; color: var(--text); text-decoration: none; display: flex; align-items: center; gap: var(--spacing-sm); }

.article-card { background: var(--bg-card); border-radius: var(--radius); padding: var(--spacing-lg); margin-bottom: var(--spacing-md); box-shadow: var(--shadow); transition: var(--transition); }
css
/* ❌ 错误 — 多行格式（禁止） */
.site-header {
    background: var(--bg-card);
    border-bottom: 1px solid var(--border);
    padding: var(--spacing-md) 0;
}
2.4 JavaScript 标准
要求	说明
严格模式	使用 "use strict";
变量声明	使用 const / let，禁止使用 var
分号使用	语句末尾必须加分号
事件绑定	使用 addEventListener()，禁止行内事件（onclick）
注释规范	复杂逻辑添加注释说明
3. CSS 内联禁止规范
3.1 禁止使用 <style> 内联
html
<!-- ❌ 错误 -->
<head>
    <style>
        .foo { color: red; }
    </style>
</head>

<!-- ✅ 正确 -->
<head>
    <link rel="stylesheet" href="/css/style.css">
</head>
3.2 禁止使用 style 属性
html
<!-- ❌ 错误 -->
<div style="padding:10px;color:red;">内容</div>
<div style="display:flex;gap:20px;">内容</div>

<!-- ✅ 正确 -->
<div class="content-box">内容</div>
<div class="flex-container">内容</div>
3.3 允许的例外情况（极少数）
以下场景允许内联样式（需在代码中标注说明）：

动态计算的尺寸（如 JS 动态设置宽高）

邮件模板（邮件客户端对 CSS 支持有限）

第三方组件集成（需用户明确要求）

5. 代码输出方式规范（v1.2 新增）
5.1 升级方式选择
改动规模	推荐方式	说明
配置文件单行值	手动修改 或 Bash（sed）	如 debug: true → false
1-5行代码	手动修改（告知文件+行号）	给你修改前后对比
6-20行代码	Bash 脚本（删除+插入）	基于行号，不依赖匹配
>20行或多文件	完整文件覆盖	直接给你完整文件内容
5.2 Bash 升级脚本标准格式
bash
#!/bin/bash
# ======================================================
# Lighttp vX.X.X - 升级说明
# 功能：xxx
# 运行：bash upgrade-vX.X.X.sh
# ======================================================

set -e

echo "=========================================="
echo "  Lighttp vX.X.X - 升级"
echo "=========================================="
echo ""

RED='\033[0;31m'
GREEN='\033[0;32m'
YELLOW='\033[1;33m'
NC='\033[0m'

# 检查是否在项目根目录
if [ ! -d "app" ] || [ ! -d "public" ]; then
    echo -e "${RED}错误：请在 Lighttp 项目根目录下运行此脚本${NC}"
    exit 1
fi

# ==============================================
# 1. 备份
# ==============================================
echo -e "${YELLOW}[1/3] 备份原文件...${NC}"
BACKUP_DIR="app/backup_$(date +%Y%m%d_%H%M%S)"
mkdir -p "$BACKUP_DIR"
cp app/controllers/TargetController.php "$BACKUP_DIR/" 2>/dev/null || true
echo -e "${GREEN}备份已保存至: $BACKUP_DIR${NC}"

# ==============================================
# 2. 删除旧代码（行号范围）
# ==============================================
echo -e "${YELLOW}[2/3] 删除旧代码（第 X-Y 行）...${NC}"
sed -i 'X,Yd' app/controllers/TargetController.php

# ==============================================
# 3. 插入新代码
# ==============================================
echo -e "${YELLOW}[3/3] 插入新代码...${NC}"
sed -i 'Xi\
新代码行1\
新代码行2\
新代码行3' app/controllers/TargetController.php

# ==============================================
# 完成
# ==============================================
echo ""
echo -e "${GREEN}=========================================="
echo "  ✅ Lighttp vX.X.X 升级完成！"
echo "=========================================="
echo ""
echo "📁 备份位置：$BACKUP_DIR"
echo ""
5.3 脚本编写规则
规则	说明
先备份	所有升级脚本第一步必须备份原文件
先删后插	删除旧代码，再在同一位置插入新代码
行号准确	必须确认删除的起止行号
原样插入	新代码保持原有缩进和格式
可重复执行	脚本执行多次结果一致（幂等）
5.4 禁止事项
禁止	原因
❌ 用 sed 正则匹配替换复杂 PHP 代码	容易匹配到错误位置
❌ 用 sed 修改混合 HTML/PHP 的代码块	转义字符复杂
❌ 不备份直接修改	无法回滚
