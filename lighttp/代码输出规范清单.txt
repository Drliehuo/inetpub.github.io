1. 核心原则：禁止造轮子（v1.3 新增）

1.1 基本原则
原则	说明
优先使用成熟方案	遇到通用问题（Session、数据库、缓存等），优先使用 GitHub 上成熟的开源方案
禁止自行造轮子	不自行实现已被广泛解决的基础功能（如 Session 管理、数据库连接池等）
参考主流框架	参考 Laravel、Symfony 等主流框架的成熟实现
试错成本控制	自行实现的基础功能往往存在未知 Bug，测试成本远高于使用成熟方案

1.2 具体场景
场景	❌ 禁止	✅ 推荐
Session 管理	自己写 session_start() 和 $_SESSION 操作	参考 Laravel Session 管理方式，封装 Session 类
数据库连接	每次查询创建新 PDO 连接	使用单例模式复用 PDO 连接
密码哈希	自己实现加密算法	使用 password_hash() / password_verify()
路由系统	自己实现复杂的路由解析	使用现有的简单路由方案（当前已实现）
CSRF 防护	自己实现 Token 生成和验证	使用成熟的 CSRF Token 方案（当前已实现）
分页功能	自己实现分页逻辑	参考主流框架的分页实现（当前已实现）

1.3 检查清单
在输出任何基础功能代码前，必须确认：
- 是否已搜索 GitHub 上的成熟方案？
- 是否参考了 Laravel/Symfony 等主流框架的实现？
- 是否避免了自己从零实现通用功能？
- 如果是自行实现，是否有充分的理由？


2. CSS 与 JS 本地化规范

2.1 禁止使用第三方 CDN 资源
❌ 禁止	✅ 允许
<script src="https://cdn.jsdelivr.net/...">	<script src="/js/app.js">
<link rel="stylesheet" href="https://cdn...">	<link rel="stylesheet" href="/css/style.css">
@import url('https://fonts.googleapis.com/...')	使用系统字体栈
任何第三方在线资源	所有资源存放于项目 public/css/ 和 public/js/ 目录

2.2 例外情况
以下情况可破例使用第三方资源（需在代码中标注说明）：
- 图标字体 — 可使用 Font Awesome 等（但建议使用 Unicode 替代）
- 富文本编辑器 — 如需集成 TinyMCE 等，需用户明确要求
- 图表库 — 如需集成 ECharts 等，需用户明确要求


3. W3C 开发标准规范

3.1 HTML 标准
要求	说明
DOCTYPE	必须声明 <!DOCTYPE html>
字符编码	必须声明 <meta charset="UTF-8">
视口设置	必须声明 <meta name="viewport" content="width=device-width, initial-scale=1.0">
语义化标签	使用 <header>、<nav>、<main>、<article>、<section>、<footer> 等
img 标签	必须包含 alt 属性
a 标签	必须包含 href 属性
表单控件	必须包含 <label> 并正确关联 for / id
属性规范	属性值必须使用双引号包裹
标签闭合	所有标签必须正确闭合

3.2 CSS 标准
要求	说明
选择器命名	使用 BEM 或语义化命名（如 .article-card、.nav-link）
注释规范	重要模块添加注释说明
单位使用	优先使用 rem / em，避免 px（边框除外）
颜色使用	使用 CSS 变量（var(--ms-blue)）便于主题切换

3.3 CSS 格式规范
所有 CSS 规则必须保持单行格式：
/* ✅ 正确 — 单行格式 */
.site-header { background: var(--bg-card); border-bottom: 1px solid var(--border); padding: var(--spacing-md) 0; position: sticky; top: 0; z-index: 100; box-shadow: var(--shadow); }

/* ❌ 错误 — 多行格式（禁止） */
.site-header {
    background: var(--bg-card);
    border-bottom: 1px solid var(--border);
}

3.4 JavaScript 标准
要求	说明
严格模式	使用 "use strict";
变量声明	使用 const / let，禁止使用 var
分号使用	语句末尾必须加分号
事件绑定	使用 addEventListener()，禁止行内事件（onclick）
注释规范	复杂逻辑添加注释说明


4. CSS 内联禁止规范

4.1 禁止使用 <style> 内联
<!-- ❌ 错误 -->
<head>
    <style>
        .foo { color: red; }
    </style>
</head>

<!-- ✅ 正确 -->
<head>
    <link rel="stylesheet" href="/css/style.css">
</head>

4.2 禁止使用 style 属性
<!-- ❌ 错误 -->
<div style="padding:10px;color:red;">内容</div>

<!-- ✅ 正确 -->
<div class="content-box">内容</div>

4.3 允许的例外情况（极少数）
以下场景允许内联样式（需在代码中标注说明）：
- 动态计算的尺寸（如 JS 动态设置宽高）
- 邮件模板（邮件客户端对 CSS 支持有限）
- 第三方组件集成（需用户明确要求）

6. 代码输出方式规范

6.1 升级方式选择
改动规模	推荐方式	说明
配置文件单行值	手动修改（告知文件+行号）	如 debug: true → false
1-5行代码	手动修改（告知文件+行号）	给你修改前后对比，你自己改
6-20行代码	提供完整代码块	你找到对应位置复制粘贴
>20行或多文件	完整文件覆盖	直接给你完整文件内容，你覆盖

6.2 禁止事项
禁止	原因
❌ 用 sed 正则匹配替换复杂 PHP 代码	容易匹配到错误位置
❌ 用 sed 修改混合 HTML/PHP 的代码块	转义字符复杂
❌ 不备份直接修改	无法回滚
❌ Bash 行号删除+插入	经实测不可靠，经常无效（已废弃）
❌ 自行实现基础功能（造轮子）	试错成本高，优先使用成熟方案（v1.3 新增）

8. 代码输出前置验证规范（v1.5 新增）

8.1 核心原则
在输出任何代码给用户之前，必须先在逻辑上完成完整的推演验证。
而且必须完整输出源代码，也就是说，必须在用户完整的源代码上进行增量、修改完成后，再完整的输出代码给用户。（否则会遗漏之前的代码，导致系统功能性缺失）

原则	说明
逻辑自洽	输出的代码在逻辑上必须是完整且自洽的
语法正确	确保 PHP/HTML/CSS/JS 语法正确，无拼写错误
依赖完整	确保所有依赖的类、方法、变量都已正确定义
SQL 正确	确保 SQL 语句语法正确，表名、字段名、别名无误
权限匹配	确保权限控制逻辑与需求描述一致
路由匹配	确保新增或修改的路由与控制器方法匹配

8.2 输出前验证清单
- [ ] 所有新增的方法是否已在类中正确定义？
- [ ] 所有调用的方法是否存在且参数正确？
- [ ] JOIN 查询中的表别名是否在所有条件中一致使用？
- [ ] WHERE 条件中的字段是否明确指定了表别名（避免歧义）？
- [ ] 新增的路由是否在 routes.php 中正确定义？
- [ ] 权限检查逻辑是否覆盖了所有场景？
- [ ] HTML 表单中的 action 路径是否正确？
- [ ] 重定向路径是否正确？

8.3 用户测试成本说明
用户测试并部署一次的成本包括：
- 代码覆盖/修改操作时间
- 清除缓存时间
- 登录验证时间
- 功能测试时间
- 若出错，还需回滚、排查、重新部署

因此，输出的代码必须做到：
✅ 零语法错误 — 用户复制即可用
✅ 零逻辑漏洞 — 用户无需自行修复
✅ 零歧义 SQL — 不会出现 Ambiguous column 错误
✅ 完整功能闭环 — 修改一处，关联处同步更新


9. v1.1.0 主题风格规范（新增）

9.1 设计语言
Lighttp v1.1.0 采用 Microsoft Fluent Design 设计语言，特点如下：
- 配色：Microsoft 官方蓝色 (#0078d4) 为主色
- 字体：系统字体栈 "Segoe UI", -apple-system, BlinkMacSystemFont, Roboto, ...
- 圆角：2px (--ms-radius) / 4px (--ms-radius-md)
- 阴影：轻量化阴影，悬停加深
- 边框：极细边框 (#edebe9)

9.3 Windows 7 玻璃风格图片（v1.1.0 新增）
文章中图片使用 Windows 7 玻璃风格：

13. 代码压缩格式规范（v1.4 新增）

13.1 PHP 代码压缩规则

✅ 正确（压缩格式、没有多余空行，除非是新的函数或者其他的定义代码，可以空一行，再写）
<?php
declare(strict_types=1);
namespace App\controllers;
use App\models\Article;
class HomeController extends BaseController
{
    public function index(): string
    {
        return 'Hello';
    }
}

❌ 错误（非压缩格式）
<?php

declare(strict_types=1);

namespace App\controllers;

use App\models\Article;

class HomeController extends BaseController
{
    public function index(): string
    {
        return 'Hello';
    }
}


14. 页面结构完整性检查清单（v1.6 新增）

在输出任何包含 HTML 输出的代码（Controller、View）前，必须逐项确认：

[ ] <!DOCTYPE html> 是否已声明？
[ ] <html> 标签是否正确闭合？
[ ] <head> 中是否包含 <meta charset="UTF-8">？
[ ] <head> 中是否包含 <meta name="viewport">？
[ ] <head> 中是否包含 CSS 引用（/css/style.css, /css/admin.css）？
[ ] <body> 标签是否正确闭合？
[ ] </body> 前是否包含 <script src="/js/app.js">？
[ ] </html> 标签是否正确闭合？
[ ] 所有 PHP 标签是否正确闭合？
[ ] 所有 HTML 标签是否正确配对？

违反以上任何一项，禁止输出代码，必须修复后再输出。
