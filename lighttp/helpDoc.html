1. 项目概述

Lighttp — 轻量级 PHP 内容管理系统

Lighttp（Lighttp Public Cloud）是一款基于 PHP + MySQL + Redis 构建的轻量级内容管理系统。采用 MVC 架构设计，代码简洁、性能优异、安全可靠，适用于个人博客、企业官网、知识库等场景。

核心设计理念

  • 极速简洁 — 最小化代码依赖，页面响应时间 < 100ms
  • 安全优先 — PDO 预处理、bcrypt 密码哈希、多层防护
  • 扁平化设计 — 纯黑白灰配色，无 Emoji，专注内容
  • 完全响应式 — 适配电脑、平板、手机
  • HTML 原生支持 — 文章内容完全支持 HTML 标签

5. 安全机制

5.1 密码安全

机制实现状态
哈希算法bcrypt已启用
成本因子12已启用 (v1.0.5)
盐值策略自动随机盐值已启用
登录自动重哈希成本因子升级时自动处理已启用 (v1.0.5)

5.2 数据库安全

  • SQL 注入防护 — PDO 预处理语句 (Database::query/execute)
  • 字符集 — utf8mb4，完整 Unicode 支持
  • 索引长度 — VARCHAR(190) 兼容 MySQL 5.6 767 字节限制

5.3 Web 安全

  • XSS 防护 — 输出使用 htmlspecialchars() 转义
  • CSRF 防护 — Token 机制已实现（待启用）
  • 会话安全 — session.cookie_httponly = 1
  • 安全头 — X-XSS-Protection, X-Content-Type-Options, X-Frame-Options
  • 敏感文件保护 — .htaccess 禁止访问 config.php, install.php 等
  • 目录保护 — 禁止访问 var/, app/ 目录
  • PHP 安全 — .user.ini 禁用危险函数 (exec, shell_exec, system 等)
  • open_basedir — 限制 PHP 文件访问范围

5.4 文件系统安全

  • 目录权限 — 755 (drwxr-xr-x)
  • 文件权限 — 644 (-rw-r--r--)
  • 可写目录 — var/cache/, var/logs/, var/sessions/ (775)
  • 所有者 — 当前用户:www (宝塔面板环境)

5.5 安全工具

  • secure-permissions.sh — 一键设置文件/目录权限
  • .user.ini — PHP 安全配置
  • .htaccess — Apache 安全配置
  • migrate-passwords.php — 密码迁移检查工具

6. 数据库结构

12 张表 · MySQL 5.6+ / MariaDB 10.3+ · utf8mb4

表名说明关键字段
articles文章表id, slug(UNIQUE), title, content, status
categories分类表id, slug(UNIQUE), name, description
users用户表id, username(UNIQUE), email(UNIQUE), password(bcrypt)
comments评论表id, article_id, user_id, content, status
pages页面表id, slug(UNIQUE), title, content
links友情链接表id, name, url, sort_order
settings系统配置表id, key(UNIQUE), value, group
cache缓存表（备用）id, key(UNIQUE), value, expire_at
logs操作日志表id, user_id, action, ip, created_at
sessions会话表id(PRIMARY), data, expire_at
tags标签表id, slug(UNIQUE), name, count
article_tags文章标签关联表article_id(PRIMARY), tag_id(PRIMARY)

默认数据

  • 管理员 — 用户名 admin / 密码 password (bcrypt 成本因子 12)
  • 分类 — 技术、生活、随笔、产品、设计
  • 示例文章 — 6 篇（涵盖技术、PHP、Redis、MySQL 等主题）
  • 友情链接 — PHP官方、MySQL官方、Redis官方、GitHub
  • 系统配置 — site_name, site_description, per_page 等

索引策略

所有 UNIQUE 索引字段使用 VARCHAR(190)，兼容 MySQL 5.6 的 767 字节索引限制：

190 × 4 (utf8mb4) = 760 字节 < 767 字节 ✓

8. 代码输出规范清单

所有代码输出必须遵守以下规范

8.1 CSS 与 JS 本地化

  • ❌ 禁止使用第三方 CDN 资源（jsdelivr, unpkg, cdnjs 等）
  • ✅ 所有 CSS 和 JS 存放在 public/css/ 和 public/js/
  • ✅ 使用系统字体栈，不依赖 Google Fonts

8.2 CSS 单行格式

所有 CSS 规则必须保持单行格式：

/* ✅ 正确 — 单行格式 */
.site-header { background: var(--white); border-bottom: 2px solid var(--black); padding: 16px 0; }

/* ❌ 错误 — 多行格式（禁止） */
.site-header {
    background: var(--white);
    border-bottom: 2px solid var(--black);
    padding: 16px 0;
}

8.3 禁止 CSS 内联

  • ❌ 禁止使用 <style> 内联标签
  • ❌ 禁止使用 style="" 属性
  • ✅ 所有样式定义在独立 CSS 文件中

8.4 W3C 标准

  • ✅ <!DOCTYPE html> 必须声明
  • ✅ <meta charset="UTF-8"> 必须声明
  • ✅ <meta name="viewport"> 必须声明
  • ✅ 使用语义化标签（header, nav, main, article, section, footer）
  • ✅ 所有 <img> 必须包含 alt 属性
  • ✅ 所有 <a> 必须包含 href 属性
  • ✅ 表单控件必须包含对应的 <label>

8.5 命名规范

  • CSS 类名 — 语义化命名（.article-card, .nav-links, .admin-bar）
  • PHP 命名空间 — App\controllers, App\models, App\core
  • 文件命名 — PascalCase（HomeController.php, Article.php）
  • 路由 — 小写 + 连字符（/admin/article/create）

8.6 JavaScript 规范

  • ✅ 使用 "use strict";
  • ✅ 使用 const / let，禁止 var
  • ✅ 使用 addEventListener()，禁止行内事件
  • ✅ 语句末尾加分号

8.7 禁止使用 Emoji

  • ❌ 禁止使用 Emoji 字符
  • ✅ 使用 ASCII 字符替代（如 [A], [C], [U], [S], [X]）
  • ✅ 使用纯文本描述

9. 开发者行为习惯

AI 开发助手行为规范

9.1 输出前自检

  • ✅ 检查是否包含第三方 CDN 资源
  • ✅ 检查 CSS 是否为单行格式
  • ✅ 检查是否包含内联样式
  • ✅ 检查是否包含 Emoji
  • ✅ 检查是否符合 W3C 标准
  • ✅ 检查敏感信息是否已脱敏

9.2 代码风格

  • PHP 使用 declare(strict_types=1);
  • 使用类型声明（string, int, array, ?array）
  • 使用 htmlspecialchars() 转义所有用户输出
  • 使用 PDO 预处理语句防止 SQL 注入
  • 使用 password_hash() / password_verify()

9.3 版本管理

  • 每次发布打 Tag，不建 Branch（个人项目）
  • 版本号格式：v1.0.5（主版本.次版本.补丁）
  • 更新记录同步到 CHANGELOG.md
  • 敏感配置不上传到 GitHub

9.4 文档习惯

  • 所有功能变更同步更新文档
  • 数据库变更同步更新 SQL
  • 配置文件变更同步更新示例
  • 保持文档与代码一致

9.5 安全习惯

  • 敏感信息使用占位符（your_db_password）
  • 生产环境 debug = false
  • 定期备份数据库和文件
  • 定期清理 var/logs/

9.6 沟通习惯

  • 清晰说明每次变更的内容和原因
  • 提供完整的操作命令和步骤
  • 标注重要提醒（如安全警告）
  • 使用结构化格式（表格、代码块）

9.7 Git 管理习惯

  • 每次发版打 Tag 标记版本（如 v1.0.5）
  • 敏感文件不上传（config.php, .env, backup 目录）
  • 提交信息清晰描述变更内容
  • 保持 main 分支为最新稳定版本
