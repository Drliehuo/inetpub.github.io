1. 项目概述

Lighttp — 轻量级 PHP 内容管理系统

Lighttp（Lighttp Public Cloud）是一款基于 PHP + MySQL + Redis 构建的轻量级内容管理系统。采用 MVC 架构设计，代码简洁、性能优异、安全可靠，适用于个人博客、企业官网、知识库等场景。

核心设计理念

  • 极速简洁 — 最小化代码依赖，页面响应时间 < 100ms
  • 安全优先 — PDO 预处理、bcrypt 密码哈希、多层防护
  • 扁平化设计 — 纯黑白灰配色，无 Emoji，专注内容
  • 完全响应式 — 适配电脑、平板、手机
  • HTML 原生支持 — 文章内容完全支持 HTML 标签

5. 安全机制

5.1 密码安全

机制实现状态
哈希算法bcrypt已启用
成本因子12已启用 (v1.0.5)
盐值策略自动随机盐值已启用
登录自动重哈希成本因子升级时自动处理已启用 (v1.0.5)

5.2 数据库安全

  • SQL 注入防护 — PDO 预处理语句
  • 字符集 — utf8mb4，完整 Unicode 支持
  • 索引长度 — VARCHAR(190) 兼容 MySQL 5.6 767 字节限制

5.3 Web 安全

  • XSS 防护 — 输出使用 htmlspecialchars() 转义
  • CSRF 防护 — Token 机制（v1.0.6 已启用）
  • 会话安全 — 自定义 Cookie 前缀 lig_，HttpOnly 开启
  • 安全头 — X-XSS-Protection, X-Content-Type-Options, X-Frame-Options
  • 敏感文件保护 — .htaccess 禁止访问 config.php, install.php 等
  • 目录保护 — 禁止访问 var/, app/ 目录
  • PHP 安全 — .user.ini 禁用危险函数
  • open_basedir — 限制 PHP 文件访问范围

6. 数据库结构

12 张表 · MySQL 5.6+ / MariaDB 10.3+ · utf8mb4

表名说明关键字段
articles文章表id, slug(UNIQUE), title, content, status, author_id
categories分类表id, slug(UNIQUE), name
users用户表id, username(UNIQUE), email(UNIQUE), password(bcrypt), nickname
comments评论表id, article_id, user_id, content, status
pages页面表id, slug(UNIQUE), title, content
links友情链接表id, name, url, sort_order
settings系统配置表id, key(UNIQUE), value
cache缓存表（备用）id, key(UNIQUE), value, expire_at
logs操作日志表id, user_id, action, ip
sessions会话表id(PRIMARY), data, expire_at
tags标签表id, slug(UNIQUE), name
article_tags文章标签关联表article_id(PRIMARY), tag_id(PRIMARY)

默认数据

8. 代码输出规范清单

所有代码输出必须遵守以下规范

8.1 CSS 与 JS 本地化

  • ❌ 禁止使用第三方 CDN 资源
  • ✅ 所有 CSS 和 JS 存放在 public/css/ 和 public/js/
  • ✅ 使用系统字体栈，不依赖 Google Fonts

8.2 CSS 单行格式

所有 CSS 规则必须保持单行格式。

8.3 禁止 CSS 内联

  • ❌ 禁止使用 <style> 内联标签
  • ❌ 禁止使用 style="" 属性
  • ✅ 所有样式定义在独立 CSS 文件中

8.4 W3C 标准

  • ✅ <!DOCTYPE html> 必须声明
  • ✅ <meta charset="UTF-8"> 必须声明
  • ✅ <meta name="viewport"> 必须声明
  • ✅ 使用语义化标签
  • ✅ 所有 <img> 必须包含 alt 属性

8.5 禁止使用 Emoji

  • ❌ 禁止使用 Emoji 字符
  • ✅ 使用 ASCII 字符替代（如 [A], [C], [U], [S], [X]）

8.6 升级方式规范

改动规模推荐方式
配置文件单行值手动修改（告知文件+行号）
1-5行代码手动修改（告知文件+行号）
6-20行代码提供完整代码块
>20行或多文件完整文件覆盖

禁止事项：不使用 Bash 行号删除+插入方案（经实测不可靠）。

9. 开发者行为习惯

9.1 输出前自检

  • ✅ 检查是否包含第三方 CDN 资源
  • ✅ 检查 CSS 是否为单行格式
  • ✅ 检查是否包含内联样式
  • ✅ 检查是否包含 Emoji
  • ✅ 检查是否符合 W3C 标准
  • ✅ 检查敏感信息是否已脱敏

9.2 代码风格

  • PHP 使用 declare(strict_types=1);
  • 使用类型声明
  • 使用 htmlspecialchars() 转义所有用户输出
  • 使用 PDO 预处理语句防止 SQL 注入
  • 使用 password_hash() / password_verify()

9.3 版本管理

  • 每次发布打 Tag，不建 Branch
  • 版本号格式：v1.0.8
  • 敏感配置不上传到 GitHub
